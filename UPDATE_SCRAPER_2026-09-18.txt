HYPER ARROW美原 スクレイパー完成版（2026-09-18）

【変更したファイル】
1. scraper_actions.py
2. .github/workflows/scrape.yml
3. requirements-scraper.txt（新規）

【変更内容】
・毎朝 08:30 JST にGitHub Actionsで実行
・マイナス差枚対策の「差枚空欄台を1台ずつ個別取得」は維持
・既存シートの取得済み差枚を再利用し、足りない台だけ個別補完
・最近6掲載分を毎朝チェックし、遅れて公開された日も自動取得
・シートは「1行あれば取得済み」ではなく、台数と差枚空欄数で完成判定
・551台未満しか一覧取得できなかった場合は既存シートを上書きしない
・一部台だけ失敗した場合は取得済み分を保存し、次回の自動実行で残りを再挑戦
・sheet.clear()をやめ、書込み失敗時に既存データが全消去されるリスクを低減
・同じスクレイパーが二重起動しないようconcurrencyを追加
・Actionsの最大実行時間を30分→60分へ変更
・スクレイパー用依存関係をrequirements-scraper.txtに分離

【GitHubへ入れる方法】
一番安全なのは mihara-scraper-patch.zip の中身3点だけを既存リポジトリへ上書き/追加する方法です。

GitHubの slotdash-mihara を開く
→ Add file
→ Upload files
→ patchの中身をドラッグ
→ Commit changes

.github フォルダは隠しフォルダなので、ZIPを展開してフォルダ構造のままアップロードしてください。
GitHubブラウザ上で .github/workflows/scrape.yml の更新が難しい場合は、既存のscrape.ymlを開いてEditから中身を置き換えてもOKです。

【Secrets】
既存の以下2つはそのまま使います。変更不要です。
・SPREADSHEET_ID
・GCP_CREDENTIALS

【自動実行】
毎日 08:30 日本時間。
通常実行の中で「最新レポート取得」と「最近の不足データ補完」の両方を行います。
以前の14:17補完専用実行は不要なので削除しています。

【補完の考え方】
例：9/17の551台中、3台だけ差枚が取れなかった場合
→ シートには548台分の差枚と、3台の空欄を保存
→ 次回は既存548台の差枚を保持
→ 空欄3台だけを個別ページで再取得
→ 3台取れれば完成扱い

例：9/17のレポート自体が8:30時点でまだ公開されていない場合
→ 最近の掲載レポート一覧には出ないので何もしない
→ 後日公開されたら、最近6掲載分の自動チェックで未取得日として取得

【安全装置】
現在の美原は551台前提です。
全機種ページから551台未満しか解析できなかった場合、サイト側の一時的な表示不良や構造変更の可能性があるため、その日の既存シートを上書きしません。
将来台数が551台から変わった場合は .github/workflows/scrape.yml の EXPECTED_MACHINE_COUNT を変更してください。

【手動実行】
Actions → みんレポ自動スクレイピング → Run workflow

normal:
最新レポート + 最近の不足分を確認

backfill:
最近6掲載分の不足だけ確認

target_date:
例 2026-09-17 を指定すると、その日だけ取得/補完
